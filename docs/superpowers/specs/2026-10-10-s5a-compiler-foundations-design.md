# S5a — Compiler foundations

Date: 2026-10-10 · Status: decided autonomously (user: keep developing; macOS
verification only, CI on hold).

## 1. Context

The ELAN compiler `elanc` exists today only in `reference/` (legacy sources +
patches 02–06, built with autotools by `reference/build.sh`). It is a chain:
`elanc` (tcsh script) → the interpreter exports the program (`elan --cexport
X.ref`) → **REM** (Java, 18k lines) generates C → a Makefile generated by REM
compiles it with the **C runtime** (20k lines, `libruntime-base`), the C++
**Earley** parser library (`libearley`), the choice-point library **cpl**
(`libchoice`, stack copying) and the Boehm GC → native program `a.out`.

The runtime also has an `aterm` variant (ATerm library terms, options
`-aterm`/`-atermns`); no historical test uses it, and the user considers the
ATerm work an experiment that was never really used.

## 2. Goal and success criteria

The compiler is part of the modern tree and of `make check`:

1. `src/compiler/{rem,runtime,earley,cpl,scripts}` hold the sources (legacy +
   reference patches, imported verbatim first, like the interpreter in S1);
   CMake builds REM (javac), the runtime (base variant only), libearley,
   libchoice, and installs `elanc`, the classes, the libraries and headers
   next to `elan` (`$PREFIX/bin`, `lib`, `include/elan-compiler`, `classes`).
2. `make check` also runs the compiled tests of the bench (kinds `J` and `JO`,
   410 cases) against the modern installation: 0 regressions, 0 snapshot
   differences.
3. No ATerm: the `aterm` runtime variant and the ATerm library are not built;
   `elanc -aterm`/`-atermns` stop with a clear message.
4. `elanc` is a POSIX `sh` script (no tcsh), same options and behaviour.

## 3. Decisions

| # | Decision | Reason |
|---|----------|--------|
| D1 | Import first, unchanged except the reference patches (02–06) and the removal of the aterm variant; modernisation of the compiler code (warnings, sanitizers, cpl redesign) is S5b. | Same safe path as the interpreter (S1 then S2). |
| D2 | Generated programs are built by the Makefile REM writes; its Darwin branch (patch 04) and Linux branch (patch 06) keep working; compilers come from `ELAN_CC`/`ELAN_CXX` defaults of the modern build (system Clang on macOS). The runtime libraries are compiled with the same pre-standard flags as in the reference (`-std=gnu89 -w -fcommon -fsigned-char`). | Generated C is 1990s C; modernising it is S5b. |
| D3 | `elanc` rewritten in POSIX sh with the same option parsing (the tcsh `switch` translated case by case), keeping the call sequence `elan --cexport` then `java ... rem.REM`. | tcsh is not installed by default on Linux; behaviour checked by the J/JO tests. |
| D4 | The bench runs J/JO against `--prefix` (the modern install) in `make check`; `make check` keeps I/A as before. A `make check-compiler` target runs only J/JO. | Compiled programs take longer to build; separate target for quick runs. |

## 4. Out of scope

Modernising REM, the runtime, cpl (S5b); the aterm variant (removed); CI.
